<objective>Expose builder-ready step catalog, template detail, and validation APIs so the frontend can author workflows without duplicating backend rules.</objective>

<threat_model>
<threat severity="medium">A user could publish an unsupported workflow if frontend-only checks diverge from backend validation.</threat>
<mitigation>Make `WorkflowService.validate_workflow_payload` registry-aware and require publish-time validation to reject unknown or disabled step types.</mitigation>
<threat severity="medium">Catalog metadata could leak unavailable privileged actions as executable.</threat>
<mitigation>Expose connector/extract entries as disabled with explicit `disabled_reason`, and keep required permissions visible without enabling execution.</mitigation>
</threat_model>
